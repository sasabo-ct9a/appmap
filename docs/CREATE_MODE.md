## 1. 目的と前提(locked)

- **誰が**:ノーコード経験者(§2)。理解だけでなく「作る・直す」をしたい。
- **何を**:React + Vite の Web アプリ。**出力は1スタックに固定**(確実性優先=「軽量だと確実」)。ユーザーはスタックを選ばない。
- **どんな場面で**:一言の要望から**新規にアプリを作る(主目的)**。既存改造は副次。
- **譲れない前提**:認知負荷最優先(§3.1)/ 段階的開示(§3.2)/ ノーコード語(§3.3)/ 動くものを早く(§3.4)/ 正直さ(§6.5・§6.6)。
- **設計スタンス**:視覚 = 意図、Claude Code = コード生成、テキストエディタ = 逃げ道。**「n8n for code」は不採用**(コードをノード化すると視覚プログラミングの壁に当たる)。

## 2. 画面(3ペイン + 段階的開示)

- **① 起動直後**:「どんなアプリを作りたい?」の**1問だけ**。マップもプレビューも出さない。
- **② 作業中**(生成が進むと"育つ"):左 = プレビュー(実物)/ 中央 = 意図(目的・成果物)+ マップ / 右 = Claude Code。
- 右ペインは**正直だがやさしく**:「今これをやっています」+ やさしい差分。`生ログを見る`で本物の出力に降りられる。

## 3. アーキテクチャ(5つの部品)

1. **ワークスペース管理**:プロジェクトごとの作業フォルダ(AppMap 管理下の projects ディレクトリ)。
2. **足場生成**:同梱の React+Vite テンプレを複製 → Claude Code が要望に合わせて書き換える。**ゼロから生成させるより確実**(テンプレという既知の土台を持たせる)。
3. **Claude Code 生成モード**:Rust が workspace を cwd にして `claude` を**編集許可**で起動。今の解析呼び出し(`claude_analyze`)の"書き込み版"。**生成は Claude 専用**(ローカル LLM は解析用。agentic なファイル編集は Claude Code CLI 固有)。
4. **ライブプレビュー**:workspace で `npm install` + `npm run dev`(Rust 管理の子プロセス)→ localhost を左ペインの `iframe` に表示。**Vite HMR** で編集が即反映される。
5. **git ワークスペース**:workspace を `git init` し、生成ごとにコミット。→ **差分**(git diff = やさしい差分の元)・**取り消し**(git)・**「動いた地点」保存**が無償で手に入る(ユーザーの"バックアップ"志向とも一致)。

**意図(マップ)→ コードの受け渡し**:最小ループでは「一言 → Claude が実装 → 結果を既存解析でマップ表示」= マップは**出力**。マップ編集 → 指示(マップ = **入力**)は Phase 3。

## 4. 段階的な実装計画

| Phase | 内容 | ねらい |
|---|---|---|
| **0 技術検証** | テンプレ複製 + npm + dev + iframe で「動くプレビュー」を出す配管(**Claude 不使用=枠を使わない**)/ 別途 `claude` を編集モードで1回だけ起動しファイルが書き換わるか確認 | 一番の未知(プレビュー配管・生成配管)を安く潰す |
| **1 最小ループ** | 一言 → 生成 → プレビュー(① 画面のみ。マップ・差分は後) | 中核価値の証明(§3.4) |
| **2 3ペイン + 理解マップ + やさしい差分** | 生成後に既存解析でマップ表示 / git diff をやさしく / 右 = Claude チャットで追撃 → HMR 反映 → マップ再解析 | refine ループ完成 |
| **3 マップ → コード** | マップ編集を Claude 指示に翻訳(双方向) | 最難・最後 |
| **4 書き出し/公開** | zip / フォルダを開く / デプロイ | usable deliverable |

各フェーズは単独で価値があり、単独で検証できる。

## 5. 正直なリスク・前提

- **Node/npm 必須**(生成アプリの実行に)。AppMap は既に Node 検出あり。無ければ案内。
- **生成は Claude 専用 + トークン消費が解析より多い**(agentic 編集は多ターン)。枠に注意(過去に枠を使い切った反省)。
- **npm install が遅い**(初回30秒〜数分)。「準備中」UX を丁寧に。可能なら node_modules キャッシュ/事前ウォーム。
- **生成が壊れることがある** → 生成後に自動起動して失敗を検知し、エラーを Claude に戻す**自己修復ループ**、それでも駄目なら正直に「うまく動かず、もう一度」(「確実にマップを出す」フォールバックと同じ思想)。
